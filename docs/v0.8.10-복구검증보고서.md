# BANDO HUB v0.8.10 복구 검증 보고서

기준은 배포된 v0.8.09 소스 ZIP, 같은 배포본의 수정검증보고서, v0.8.09 통합 인계서 및 운영 화면 캡처다. 이번 복구에서는 해당 소스와 운영 SQLite 백업, 공식 상품 페이지를 대조했다. 변경 파일 목록은 기준 ZIP과 파일 해시를 비교해 작성했다.

## 저장 경로와 데이터 검증

- 최초 운영 백업은 `%APPDATA%\bandostand-orders\backups`의 `before-v0810-recovery-*.sqlite`다. 실제 시작 시 쓰기 직전에도 `before-z-display-repair` 백업을 만든다.
- 대표이미지 원본은 배포 폴더의 `resources\data\product-images`에 들어 있다. 상세 화면을 열면 해시를 검증한 파일이 `%APPDATA%\bandostand-orders\product-images\bandostand`에 등록된다. BD 102M은 `326.jpg`다.
- 대표이미지 원본 확인에는 공식 상세 페이지의 상품 번호, 대형 대표 이미지와 `og:image`의 URL 일치를 사용했다. 동일 공식 페이지 내 여러 SKU는 해당 페이지 대표사진을 공유한다. 옵션별 사진이 별도로 확인된 것으로 보고하지 않는다.
- 운영 데이터 보존 대조는 복구 직전 백업과 비교한다. 이름·부제 외 상품 payload, 상품·옵션 ID와 가격, 주문·입금·운임·거래처·엑셀 이력의 행 동일성, SQLite 무결성과 외래키 상태를 확인한다.

Windows 검증은 실제 Windows 실행 파일의 격리 프로필 검사와 화면에서 수행한 운영 점검을 별도로 기록한다. 100%·125%는 앱 배율이며 Windows 시스템 DPI를 변경한 검사는 아니다. 제공한 캡처는 주문 데이터 표시를 피하도록 접수 패널과 날짜 조작부만 잘라냈다.

## 남은 확인 항목

- 운영 창은 실행과 접수 화면 진입을 확인했다. Windows 캡처 도구의 `window capture timed out`와 `coordinate input geometry is unavailable` 때문에 운영 창의 상품 상세 클릭은 확인하지 못했다. 상품 목록·상세의 캡처와 12개 검증은 동일 배포판에서 운영 백업을 사용한 결과다.
- Z 외 37개 상품 표시명은 이전 버튼 실행 후 변경이 확인됐다. 각 상품의 직원 표기 의도와 원본 옵션을 대조하는 작업은 남아 있다.
- 실제 공장 회신 파일의 세부 형식, 시스템 DPI 변경, 카카오톡 연동, 한글 IME 조합과 실제 Excel 앱 열기는 이번 검증에서 수행하지 않았다.
