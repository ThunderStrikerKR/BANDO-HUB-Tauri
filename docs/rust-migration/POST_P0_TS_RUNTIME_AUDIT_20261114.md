## Not runtime migration blockers solely because the TS file exists

- `replies.ts`: `billingSnapshot` is live; **`applyReply`, `proposeReply`** are retained original TS oracles, not confirmed invoked by the active reply UI. Do not port unused functions merely by filename.
- `orders/useOrderDesk.tsx`: callback `question()` calls `validation.pendingIssue` but is returned and **not destructured or called by `OrderDesk.tsx`**. Treat as dormant, not an active saved-customer-question transition. Rust `apply_issue_action.pending_issue` already exists and has TS parity; remove dead wrapper or connect it only after explicit UI workflow review.
- `app/OrderHistory.tsx` and `app/DailySettlement.tsx` call Rust `list_order_history_view`, `list_order_history`, `prepare_settlement`. Their imports of `app/order-history.ts` / `app/settlement-report.ts` are **type-only**, not an active TS money calculation. Keep original algorithms as parity test oracles.
- `MessageWorkspace.tsx` uses `nativeAutomaticMessage`; `automatic-message.ts` remains source oracle only, not an active copy renderer.
- `FactoryReplyImport.tsx` and `factory-reply-auto.ts` use native parser and apply. `factory-reply-workbook.ts` is used for TypeScript payload types and test oracle, not live business matching.
- `WorkflowQueue.tsx` calls Rust preparation/finalization; `factory-export.ts.createFactoryWorkbook` and `store-export.ts.createStoreWorkbook` are legitimate ExcelJS byte serializers. Keep them.
- `ClientWorkbookTools`, `ProductSyncWorkbookTools`, `RegistrationManager` use native preview/apply with TypeScript Excel export/template bytes. Keep serializers and payload types.
- `ManagementUI.tsx` exports `CatalogPanel` using old TS `catalog-price-sync`, but current `ClientManager` and `SourceDocument` mount only `TierBadge/ClientPicker` from that module; `CatalogPanel` is not confirmed mounted. Treat as dead-component review, not a functioning pricing screen.
- `workflow.ts.groupShipments`, `shipmentContext`, `domain.won`, `matching.internalModel`, `product-models.registeredProducts/sortProducts` are still read in live UI. Some are simple selectors/formatters; classify each use before deciding to port; deleting the entire module is premature.
