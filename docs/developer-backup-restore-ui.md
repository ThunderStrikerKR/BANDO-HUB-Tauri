# 개발자 TEST 모드: 실제 백업 및 복원 검증

## 작업공간과 보호 범위

- 정상 업무 창: 설정 → 개발자 모드 → **격리 테스트 작업공간 열기**.
- 새 TEST 창: `TEST / 격리 DB / 외부 발송 금지` 표시 확인.
- TEST 창의 설정 → 개발자 모드 → **TEST 백업 및 복원 검증** 패널.
- 기본 TEST SQLite 파일: `developer-test/bando-hub-test.sqlite`; 백업도 같은 TEST 폴더의 `backups` 하위에만 생성된다.
- 테스트용 주문, 거래처 및 별칭은 가상이다. 판매 업체, 택배사, 거래처로 자동 전송되지 않는다. 실제 업무 창에서 이 검증 패널은 표시하지 않는다.
- 프로그램을 종료하거나 메뉴를 바꾸면 단계별 진행 상태는 사라진다. **TEST 백업 파일 자체는 보존**된다. 이 경우 TEST 창의 일반 `데이터 백업 및 복구` 목록을 통해 수동 복원이 가능하다.

## 사용자 검증 시나리오

1. **1. TEST 백업 만들기**: 실제 SQLite 전체 파일을 백업하고 목록에 등록되는지 확인한다. 원본 주문, 거래처, 상품, 감사 기록의 기준 데이터가 화면에 나타난다.
2. **2. 가상 주문과 가격 변경**: 확인창의 `TEST 데이터 생성`을 선택한다. 실제 `state_save`와 Rust 접수 검증을 거쳐 **가격 +137원, 가상 특수 거래처 1개, 공통 및 거래처 별칭 2개, 확정 주문 1건, 접수 감사 1건**을 TEST DB에 저장한다. 출고 큐 및 외부 발송은 만들지 않는다.
3. 검증 화면에서 시험 상품명과 변경된 가격, 가상 주문 저장 결과를 확인한다. 필요하다면 TEST의 `주문내역`을 열어 확인한다. 단, 검증 화면을 떠나면 임시 검증 단계가 초기화되므로 이후 수동 복원해야 한다.
4. **3. 백업 복원 및 비교**: 복원 확인창의 `TEST DB 복원`을 선택한다. 이는 일반 백업 관리와 **동일한 native `backup_restore` 경로**를 사용한다.
5. 프로그램이 다시 TEST DB를 조회하고 상품, 가격, 거래처, 주문, 별칭, 워크플로, 설정, 접수 감사 기록을 백업 생성 시점과 대조한다. 리비전은 복원 과정에서 **증가**해야 하므로 비교에서 제외하고 별도 검사한다.
6. **복원 검증 통과**와 항목별 통과 결과를 확인한다. 백업 목록에 `pre-restore-*.sqlite` 안전 백업이 추가된 것을 확인한다.

## 보호 정책

- 백업이 없으면 2단계를, 가상 데이터를 저장하지 않으면 3단계를 실행할 수 없다.
- 백업 이후 TEST DB가 다른 작업에서 변경됐으면 검증용 데이터 쓰기를 차단한다.
- 가상 데이터 저장 이후 TEST DB가 추가 변경됐으면 자동 복원 버튼을 차단하고 TEST의 일반 백업 관리 목록을 통한 수동 확인으로 유도한다.
- 복원 경로는 사전 원본 백업, 경로 제한, SQLite 무결성 검증, 전체 백업 복원, 리비전 증가, 복원 실패 시 기존 DB 복귀를 사용한다.
- 검사에서 하나라도 불일치하면 성공 메시지를 표시하지 않는다.
- 브라우저 자동시험은 모의 Tauri IPC로 **실제 React UI와 확인창을 조작**한다. SQLite 파일 생성, 확정 주문 Rust 검증 및 DB 복원은 별도의 **Windows Rust 통합시험**으로 검증한다. 두 시험은 서로 대체하지 않는다.
- 개발 브랜치 및 Draft PR에서만 테스트하였으며 운영 SQLite 데이터, `main` 브랜치 및 앱 버전은 변경하지 않는다.

## 수동 현장 확인 시 제외하면 안 되는 항목

- 정상 업무 창에서 TEST 검증 버튼이 노출되지 않는지
- TEST 창임을 구별할 수 있는 안내와 백업 파일명이 표시되는지
- 2단계 TEST 주문이 실제 발송이나 Excel 큐에 포함되지 않는지
- 복원 확인창에서 취소하면 아무 것도 바뀌지 않는지
- 복원 완료 후 주문내역에서 가상 주문이 사라지고 실제 데이터를 포함하지 않는 기존 TEST 데이터가 돌아오는지
- 앱 종료 후 TEST 창 재실행 시 백업 파일을 다시 조회할 수 있는지
- Windows의 파일 잠금 또는 바이러스 백신 검사 중 오류가 발생하면 DB와 안전 백업이 보존되는지
