# BANDO HUB UI·코드 개발 기준 — v0.8.02

이 문서는 기존 업무 동작을 유지하면서 화면과 구현 방식을 일관되게 확장하기 위한 기준이다. 확정된 사용자 요구를 우선한다. 설계 회의 기록은 의도가 불명확할 때 참고하며 과거 제안을 새 기능으로 자동 추가하지 않는다.

## 구조

- `App.tsx`: 화면 조합. `app/useAppModel.ts`: 앱 상태·저장·화면 이동·창 제어.
- `app/`: 메뉴 정의와 주문 내역·설정·보조 화면. 관리 화면은 lazy import로 처음 사용 시 불러온다.
- `OrderDesk.tsx`: 접수 표시. `orders/useOrderDesk.tsx`: 접수 처리. 기존 도메인 모듈의 금액·파서·상태 검증을 재구현하지 않는다.
- `ui/`: Field, MoneyInput, Modal, AccountPicker, PageHeading, ScreenBoundary. `ui.tsx`는 기존 import 호환용 재내보내기다.
- `shared/`: 비동기 작업 잠금, 안내 메시지, 초안 병합, 미저장 변경 추적. React와 무관한 계산은 별도 순수 함수로 둔다.
- `styles/index.css`: 유일한 스타일 진입점. 기존 순서를 유지하는 화면별 모듈과 `tokens.css`, `components.css`를 관리한다. 비슷한 숫자 이름의 CSS 파일을 계속 추가하지 않는다.

## 화면 규칙

기본 다크 테마·Pretendard/SUIT/Roboto Mono 역할을 유지한다. 폰트 크기·두께·자간을 포커스 유무에 따라 바꾸지 않는다. 관리 화면·팝업의 기본 입력과 버튼은 100%에서 높이 40px, 표 행의 짧은 동작은 32px를 쓴다. 해당 역할의 크기는 UI 배율에 맞춰 확대한다. 접수·추적·4단계 버튼은 업무 밀도와 기존 동작을 유지하는 별도 규칙이다.

필드는 보이는 label과 실제 입력 id를 연결한다. label 안에 여러 버튼·입력을 중첩하지 않는다. MoneyInput은 포커스 중 편집용 숫자, 포커스 해제 후 천 단위 구분을 표시한다. null과 0을 임의로 같은 가격으로 확정하지 않는다. 원문·메시지는 가독성과 강조 범위를 유지한다.

화면 제목·설명·동작은 PageHeading 패턴, 빈 목록은 EmptyState 패턴을 사용한다. 필터는 좁은 폭에서 줄바꿈하며 표의 숫자는 우측 정렬한다. 오류는 기존 주황색 의미를 유지하고 장식에 같은 의미를 남용하지 않는다.

## 저장·실패·팝업

일반 비동기 버튼은 useAsyncTask를 사용한다. React 렌더링 이전의 연속 호출도 잠그며, 예외를 readableError로 안내한다. 실패 결과를 성공으로 처리하거나 입력·팝업을 먼저 지우지 않는다. 별도 업무 정책인 4단계의 2초 잠금과 DB 트랜잭션은 이 공통 처리로 대체하지 않는다.

안내는 success/error/info를 호출 시 지정한다. 성공은 3초 뒤 닫히고 오류·정보는 명시적으로 닫는다. 메시지 문구를 정규식으로 읽어 성공 여부를 추측하지 않는다. 여러 번 같은 오류가 발생해도 동일 안내를 중복 쌓지 않는다.

편집 팝업은 Modal에 draft와 busy를 전달한다. 저장 중 닫기·본문 동작을 막고 최상위 dialog로 배경 입력을 차단한다. 검색만 한 상태는 미저장 편집으로 취급하지 않는다. 실제 편집 중 앱 종료 시 기존 확인 흐름에 연결한다. 설정 화면은 useDraft로 서버 갱신과 입력을 병합하고 같은 항목 충돌은 명시적 다시 불러오기를 요구한다.

ScreenBoundary는 화면 렌더링 실패를 격리하고 저장된 데이터를 다시 불러오는 동작을 제공한다. 복구 중 오류도 안내하며 잘못된 데이터를 자동 수정·삭제하지 않는다.

## 검사와 변경 제한

`npm run check:quality`, `npm run build`, `npm test`, `npm run test:ui`를 수행한다. 배포 전 `npm run package:folder`, `npm run test:packaged` 및 Portable 실행 검사를 수행한다. 실제 외부 창·기기 검사는 수행 여부와 한계를 별도로 기록한다. 화면 캡처만으로 저장 동작까지 검증했다고 보고하지 않는다.

배포 스크립트는 공유 node_modules를 재사용하지 않고 `work/package-stage`에 잠금 파일 기준으로 부품을 설치한다. ASAR 내부 필수 의존 관계 검사를 통과한 뒤 실제 배포 EXE로 엑셀 다운로드·업로드·업무 회귀를 수행한다. TypeScript 빌드 성공만으로 배포 파일이 완성됐다고 판단하지 않는다.

DB는 기존 사용자 데이터 경로에 유지한다. 운영 DB를 테스트에 쓰지 않으며 복사본·격리 프로필을 사용한다. DB·가격 스냅샷·모델코드 충돌 시 직원 확인·원문 감사·입금·엑셀 형식·기존 단계의 정책은 구조 정리만을 이유로 바꾸지 않는다. 일일 결산 등 미확정 기능에 가상 업무 값을 넣지 않는다.

## v0.8.04 접수 정책

발주 원문은 읽기 전용으로 유지하고 `붙여넣기`로 전체 교체한다. 새 접수는 ‘주문 확인 완료’ 이전까지 메모리 초안이며, 교체·초기화·수동 분류·다른 마스터 저장을 정식 주문/감사 저장으로 연결하지 않는다. 정식 확정은 기존 단계 검증과 DB 경계 검증을 거쳐 원문·확정 시각·전체 스냅샷·단계 기록을 원자적으로 저장한다. 기존 저장 주문의 감사는 보존한다.

수동 분류는 최신 직원 정정값을 상속한다. 원문 블록 배정 관계와 셀 최종값을 구분하고, 회수할 때 직원 보완값을 보호한다. 상품 변경 후 수량을 자동 승계하거나 1개로 정하지 않는다. 수량 확정 전 편집을 제한하고 상품/모달 취소를 제공한다. 원문 블록 클릭이 선택 셀의 초점을 빼앗지 않도록 한다. 입력 버퍼도 초기화 되돌리기와 미저장 상태에 포함한다.

선택 데이터의 갱신을 애니메이션 완료까지 미루지 않는다. 표시 효과와 실제 편집 대상 ID가 엇갈리지 않도록 선택은 즉시 반영한다. AI 버튼은 disabled 더미이며 분석·외부 전송을 연결하지 않는다.
