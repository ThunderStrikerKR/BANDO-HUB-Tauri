# BANDO HUB Tauri v0.0.3 - 계좌 설정 및 거래처별 계좌

## 문제

- 입금 계좌를 저장한 뒤 반도스탠드, 반도몰 추천계좌를 지정할 때 설정 저장이 거부될 수 있었다.
- v0.0.2 설정 화면은 작은 변경에도 전체 상태를 `state_save`로 전달하며, Rust는 전역 revision 차이를 거부했다.
- 오류 문구가 수집되지 않아 실제 실패 지점을 단정할 수 없지만, 구조적으로 불필요한 전역 충돌을 제거했다.

## 수정 내용

1. `settings_patch` Rust 명령 신설. 변경된 설정 최상위 필드만 병합한다. 현재 DB의 같은 설정 키가 기대한 값과 다른 경우에만 저장을 차단한다.
2. 추천계좌는 등록된 은행명, 계좌번호, 예금주가 모두 채워진 계좌만 선택 및 저장할 수 있다.
3. 거래처 관리에 `주 사용 입금계좌` 선택 추가. 주문 직접 지정 > 거래처별 주 사용 > 반도스탠드/반도몰 추천 순서로 적용한다. 소매 주문은 거래처 설정을 사용하지 않는다.
4. 거래처 관리 UI에 거래처명, 송장 표시 상호, 거래처 별칭의 용도 설명 추가.
5. 신규 또는 변경된 거래처는 상호, 주소, 연락처(전화나 휴대폰 한 개 이상), 가격등급이 필요하다. React와 Rust 양쪽에서 검증한다.
6. 거래처가 주 사용으로 쓰는 계좌는 삭제를 차단한다.
7. 기존 앱 식별자 및 DB 파일명 `bando-hub-v001.sqlite` 유지. 상품 가격과 기존 시험 데이터는 자동 삭제하지 않는다.

## Windows 확인 순서

1. 기존 v0.0.2 EXE를 안전하게 보관한다.
2. `BUILD_WINDOWS_TAURI.cmd`로 v0.0.3을 빌드한다.
3. 설정 → 계좌 등록 → 반도스탠드 추천계좌 및 반도몰 추천계좌 지정 → 설정 저장 → 설정 재진입 후 확인한다.
4. 거래처 신규 등록에서 주소와 전화/휴대폰 누락 시 저장이 차단되는지 확인한다.
5. 거래처에 주 사용 계좌를 지정하고, 주문에서 수동 계좌를 지정하지 않은 경우 안내 계좌가 선택되는지 확인한다.
6. 주문에서 다른 계좌를 직접 지정할 때 수동 계좌가 우선하는지 확인한다.
7. 프로그램을 재실행하여 기존 상품 가격과 추천계좌 및 거래처별 계좌가 유지되는지 확인한다.

## 검증 한계

- Node 테스트와 TypeScript 구문 검사만 수행. Rust toolchain과 Windows 컴파일러가 없는 환경으로 Rust 컴파일 및 Windows 실행은 아직 미검증.
- 전용 브라우저, MCP, OCR AI 분석, 카카오톡 도킹과 Excel 이전 기능은 이번 변경 범위가 아니다.
