# BANDO HUB: 관리 화면 공통 UI 규칙

적용 범위: 주문 내역, 엑셀 관리, 일일 결산, 상품 관리, 운임 관리, 거래처 관리, 설정의 주요 화면과 목록.

## 구조와 배치
1. 모든 화면의 제목은 공통 `PageHeading`을 사용한다. 글씨 크기와 기준선, 제목 아래 간격을 개별 화면에서 변경하지 않는다.
2. 상단에는 제목 및 주요 작업 버튼, 그 아래에는 화면에 존재하는 하위 탭, 다음에는 검색과 필터, 마지막으로 실무 목록 또는 상세 콘텐츠를 배치한다. 탭이나 검색이 없는 화면에서는 해당 단계를 생략한다.
3. 검색창은 `ManagementSearch`를 재사용하고 화면마다 비슷한 입력창을 새로 만들지 않는다. 운임관리의 검색 디자인(좌측 검색 표시, 짙은 입력 배경, 통일된 높이)을 기준으로 한다.
4. 업무 필터, 선택 항목 수, 날짜 이동은 검색창과 같은 도구 영역에서 관련성에 따라 묶는다.
5. 설정의 역할 탭도 공통 `management-tabbar`를 사용한다.
6. 카카오톡 예약 영역 및 사용자 설정 화면 배율은 유지한다.

## 표와 밀도
1. 표의 열 너비는 콘텐츠의 중요도와 길이에 따라 결정한다. 긴 상품명, 주소, 원문은 충분한 가로폭을 유지한다.
2. 셀의 부가 정보는 공간이 충분할 때 같은 줄에 표시한다. CSS `display:block` 때문에 억지로 줄바꿈하지 않는다.
3. 셀 상하 여백과 버튼 높이를 통일한다. 한 행에 텍스트만 들어가는 표는 고정된 큰 높이를 만들지 않는다.
4. 버튼은 같은 행에서 수직 중앙에 정렬하고, 버튼끼리 충분한 간격을 둔다.
5. 열이 실제로 많아지면 표 콘텐츠를 억지로 여러 줄로 압축하지 않고 해당 표의 가로 스크롤을 제공한다.
6. 임의의 데이터 생략이나 숨김은 금지한다. 선택한 상세 보기로 늘어나는 내용은 사용자가 확장했을 때 표시한다.

## 유지보수와 스타일 소유권
- 디자인 토큰(`src/styles/tokens.css`)과 공통 컨트롤(`src/styles/components.css`)을 기본으로 한다. 제목과 검색/탭/공통 표의 화면 배치는 `src/styles/management-layout.css`이 담당한다.
- 상품관리 고유 패널과 대표색상 폼의 레이아웃은 `src/styles/product-admin-redesign.css`, 운임관리 고유 폼 및 그룹별 액션 레이아웃은 `src/styles/shipping.css`에서 관리한다.
- **최종 CSS 파일에 덮어쓰기 규칙만 추가하는 방식은 완료 기준이 아니다.** 동일 요소를 제어하는 기존 선언을 확인하고, 중복 선언을 원래 소유 파일에서 제거하거나 공통 컴포넌트 스타일로 이동한다. 임시 우선순위 추가가 필요하다면 해당 충돌 원인과 제거 조건을 남긴다.
- 공통 `PageHeading`, `ManagementSearch`, `Button`, `Field`, `EmptyState` 및 `management-search-toolbar`, `management-tabbar`, `management-data-table`을 우선 재사용한다. 사용자 선택 자체가 기능인 트리 행과 같은 특수 조작 요소는 무조건 `Button`으로 교체하지 않는다.
- 입력 폼은 레이블과 컨트롤을 `Field`로 연결하고, 동일한 역할의 버튼은 `Button`의 용도별 변형을 사용한다. 폼 행과 목록 행의 여백은 해당 레이아웃의 소유 CSS에서 정한다.
- JSX/CSS 구조 검사뿐 아니라 **실제 렌더링의 계산된 크기와 좌표**, 입력 및 저장 동작, 창 폭에 따른 줄바꿈을 확인한다.
- 기능 및 데이터 저장 정책은 화면 구조를 변경한다는 이유로 변경하지 않는다.

## 단계별 적용 현황
- 1단계: 브랜드 및 별칭 관리 입력 폼, 등록 목록, 정정 버튼을 공통화. 미저장 전환 테스트와 실제 행 간격 검사 추가.
- 2단계: 대표색상 관리와 운임 그룹 관리의 새 그룹 입력, 공통 버튼, 목록 조작 높이와 여백을 적용. 검증 완료 여부는 해당 GitHub Actions 실행 결과로 판정.
- 3단계: `ManagementTable`을 주문내역, 일일결산, 상품 목록, 상품별 기본 운임, 배송그룹 지정 및 운임 이력, 거래처 목록, 엑셀 발송 대기 및 작성 이력, 공장 회신 이력의 목록에 적용한다. 컴포넌트는 별도의 DOM 래퍼를 만들지 않으므로 기존 `thead`, `tbody`, 행 이벤트 및 가로 스크롤 정책을 유지한다.
- 3단계: 목록 결과 없음에는 `EmptyState compact`를 사용한다. 이 컴포넌트는 좌측 정렬, 작은 상하 여백을 가지며, 화면 전체의 로딩 및 오류 상태가 쓰는 기본 `EmptyState`와 구분한다. 엑셀과 운임의 결과 스크롤 영역은 결과가 전혀 없을 때만 높은 최소 높이를 해제한다.
- 3단계: `components.css`의 구형 `table`/셀 기본 규칙과 `shipping.css`의 구형 표 패딩/글씨 규칙은 `management-data-table` 외의 레거시 표로 적용 범위를 좁힌다. 공통 표의 패딩, 글씨 크기 및 버튼 밀도는 `management-layout.css`에서 관리하며, 운임 배정 목록의 선택창은 업무 전용 높이 변형을 `shipping.css`에 둔다.
- **검증 기준:** 빈 검색 결과에도 표 헤더는 표시, 결과 없음 안내는 80px 이하의 간결한 높이, 공란인 엑셀 및 운임 목록의 높이는 데이터 없는 상태에만 축소, 상품명과 주소 열에 임의의 좁은 폭 적용 금지. 실제 React 렌더링과 저장 확인 동작을 함께 검사한다.
- **미완료:** 다른 관리 화면의 공통 컴포넌트 전환, CSS 전 파일 선택자 충돌 완전 제거, 전 하위 탭의 스크린샷 비교 및 Windows EXE 육안 검수. 이 문서는 전체 UI 정규화 완료를 의미하지 않는다.
