# v0.0.2 작업내역 및 보류 범위

## 목적

v0.0.1에서 Windows 빌드, 앱 실행, 상품 가격 저장까지 사용자 확인 완료. 다음 우선순위인 접수/수동 분류를 Tauri Rust SQLite 경계에서도 보호하기 위해 변경.

## 변경 소스

- `src-tauri/src/reception.rs`: 새 Rust 주문 접수 검증, 기존 확정 원문/확정 스냅샷/정정 기록 보호, 아카이브 항목 계산, 단위 테스트
- `src-tauri/src/lib.rs`: Rust 저장 트랜잭션 검증, 주문 인덱스, 독립 원문 감사 테이블, 조회 명령, v0.0.1 DB 제자리 호환
- `src/tauri-bridge.ts`: `receiptArchive` Rust 명령 연결
- `src/ReceiptArchive.tsx`: 기록 조회 오류 표시 및 설명 수정
- `src/app/AppHeader.tsx`: 현재 미지원 안내 버전 수정
- `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `package.json`, `BUILD_WINDOWS_TAURI.cmd`: 버전 v0.0.2
- `tests/tauri-reception-wiring.test.mjs`: JS 정적 연결 검사

## 검증

- `npm test`: 7개 통과 (기존 상품 시드 4개 + 버전/DB 경로/연결 3개)
- `cargo test`: **실행 불가** (작업 환경에 Rust 없음); Rust 단위 테스트 5개는 코드에 포함
- Windows Release EXE 생성: **실행 불가** (작업 환경에 Windows/MSVC 없음)
- Windows 사용자 기기에서 수행할 테스트: README 참조

## 주의 사항

- 현재 `state_save`는 SQLite의 `app_state` JSON 스냅샷을 정본으로 사용합니다. 개별 주문 전용 테이블 분리, 주문 전용 API, 완전한 DB 무결성 검증까지 완료된 상태는 아닙니다.
- Rust 경계 검증은 UI의 전체 `validateReceptionBoundary` 로직과 완전히 같은 범위가 아닙니다. 프론트엔드 검증을 유지한 상태로 단계적으로 이전합니다.
- 감사 테이블은 원문 확인용 기본 기록입니다. 법적 증거 보관 수준의 위변조 방지 체계는 별도입니다.
- v0.0.1에서 변경한 상품 가격과 앱 설정이 유지되도록 앱 데이터 경로를 **고의로 변경하지 않았습니다.**
