# 반도허브 360개 독립 상품 이관 및 검수표

## 정본 기준

- **업무용 상품 1개 = 실제 주문 가능한 완성 판매 구성 1개**. 옵션 선택·SKU 분리·모델명 자동병합을 하지 않는다.
- 홈페이지 등록 목록 303개는 원본 데이터일 뿐, 반도허브의 실제 상품 개수가 아니다. 해당 303개 항목에서 확인된 360개 판매 구성을 **360개의 독립 상품 ID**로 등록한다.
- 기존 303개 자료는 `src-tauri/resources/legacy-state-seed-303.json`에 원본 보존한다. 새 정본은 `src-tauri/resources/state-seed.json`.
- 개발 브랜치에서 **360개 상품, 각 1개 가격 기록, 360개 고유 가격기록 ID**. 기존 가격(도매/반도매/소매), 카페24 원본 옵션 ID, 공식 URL과 사이트 상품번호 보존.
- 같은 모델명이어도 색상, 상판, 바퀴, 길이, 악기 종류, 부속품 구성 등이 다르면 다른 상품 ID. 실제 업무용 상품명에 구분 정보를 명시한다.
- `상품설명`은 매장 직원 전용 참고 정보. 원본과 충돌하거나 누락된 정보는 확인 대상으로 보류한다.
- 기존 `variantId`는 새 구조에서 **과거 가격 기록과 공식 소스의 식별을 위한 호환 키**이며, 직원이 선택하는 상품 옵션이 아니다. 네이티브 저장에서는 `core_product_prices`의 상품당 1개 가격 기록으로 보관한다.
- 원본 DB에 확정 주문/별칭 등의 참조가 있으면 ID를 임의 치환하지 않는다. 정확한 구분 ID가 없으면 마이그레이션을 중단하고 안전 백업 보존.
- 운영 DB, 본 브랜치 외의 소스 및 `main` 변경 금지. 신규 앱 빌드 실제 Windows 현장 검증은 별도 필요.

## 추가 검토 우선순위

1. 동일 상품명을 가진 두 공식 상품번호의 상품이 실제로 같은 제품인지. 제품이 같더라도 근거 없이 상품을 합치지 않는다.
2. P코드만 존재하는 상품의 실제 제조 모델코드 존재 여부. P코드로 새로운 모델명을 임의 생성하지 않는다.
3. 사이트에 색상이 미표기된 제품의 구성 확인. 없는 옵션을 임의로 만들지 않는다.
4. 상판 타입 표기가 다르게 등록된 LP-WA/LP-WB의 실제 상품 구조와 제조 모델코드를 확인.
5. 공식 홈페이지 가격과 내부 수동 가격의 차이는 승인 없이 덮어쓰지 않는다.
