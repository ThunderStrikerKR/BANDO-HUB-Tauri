## 검증 목적

1. UI 배율을 변경해도 메뉴나 전체 작업 화면 밖으로 불필요한 세로 스크롤바가 생성되지 않는다.
2. 상품 목록, 운임 목록, 거래처, 주문/결산/Excel, 설정 등 각 작업 화면이 화면 높이 안에 유지된다.
3. 상품·거래처 상세 모달과 긴 내용의 공통 모달이 화면 밖으로 밀리거나 잘리지 않는다.
4. 좁은 화면에 꼭 필요한 가로 스크롤은 삭제하지 않는다. 실제 데이터와 주요 액션에 계속 접근할 수 있어야 한다.

## 검증 조건

- **배율**: 90%, 100%, 110%, 125% (실제 기본 설정의 '전체 UI 크기' 콤보박스로 변경 후 CSS의 `--ui-scale` 적용값 검사)
- **창 크기**: 1920×1080, 1600×900, 1280×800, 1024×700
- **기본 화면**: 상품관리 목록, 운임관리 상품별 기본 운임, 거래처관리 목록, 기본설정, 엑셀관리, 일일결산, 주문내역, 동급 배송 그룹 지정. **8종 × 4배율 × 4화면 = 128개 상태**
- **추가 하위 탭**: 카테고리 관리, 대표색상 관리, 별칭 관리, 브랜드 관리, 동급 그룹 운임표, 조합/기준 이력, 공장 엑셀 대기, 매장 발송 대기, 엑셀 작성 이력, 자동 메시지 편집. 10종을 **극단 조건(90%, 125% × 1920×1080, 1024×700)**에서 검증해 40개 상태 추가.
- **모달**: 상품 상세, 거래처 상세 (4배율 × 4화면 × 2종 = 32개), 긴 내용의 공통 모달 (극단 조건 4개). 총 **36개 조합**.
- 환경: GitHub Actions Playwright Chromium에서 실제 React를 띄운 뒤 **모의 Tauri IPC와 합성 업무 데이터** 사용. 실운영 데이터는 변경하지 않는다.

## 설계 및 구현 원칙

- 바깥쪽 페이지나 내비게이션을 컨텐츠 높이만큼 늘리는 방식은 사용하지 않는다. `.hub-shell-scroll`, `.management-container`은 화면 높이 범위에 고정한다.
- `.product-list-workspace .price-table-scroll`, `.shipping-product-list .shipping-table-scroll`, `.shipping-assignment-list .shipping-table-scroll`, `.settings-tab-panels` 등 개별 작업 영역이 스크롤한다.
- 카카오톡 예약 공간을 없애거나, 화면에서 접근할 수 없는 내용으로 잘라내어 테스트를 통과시키는 변경은 금지한다.
- 공통 모달은 7단계의 `--modal-title-size`, `--modal-close-height` 등 디자인 토큰을 사용한다. 상태에 따른 변경과 창 크기를 함께 검증한다.
- `scripts/receipt-audit-ui-smoke.mjs`의 `STAGE8_SAMPLE`, `STAGE8_MODAL`, `STAGE8_MATRIX` 로그는 향후 CSS 변경 후 자동으로 같은 조건을 재검사할 수 있는 증거다.
- 시험 도중 변경한 기본설정 UI 배율은 테스트가 끝날 때 100%로 돌려놓는다.

## 이 단계에서 아직 검증하지 못한 항목

- **실제 Windows Tauri EXE를 화면에 띄워 직접 검수**하는 것은 9단계 범위다. Windows CI가 EXE를 컴파일하더라도 GUI를 수동으로 확인했다는 뜻이 아니다.
- 모든 팝업의 모든 내용 상태를 16개 조합에서 완전히 재현한 것은 아니다. 7단계에서는 23개 모달 상태를 **기준 배율에서**, 8단계에서는 대표 편집 및 긴 본문 모달을 **교차 배율에서** 검사했다.
- 화면 캡처를 기반으로 한 픽셀 단위 스냅샷 비교 및 실제 Windows 폰트 렌더링은 수행하지 않았다.
- 앱의 최소 지원 창 크기보다 좁은 경우 반드시 가로 스크롤 접근이 필요할 수 있다. 좁은 화면에 맞춘답시고 상품명/표를 숨기지 않는다.

## 검사 통과/완료 판단

8단계의 **React 브라우저 교차 배율 검증**은 위 범위에서 PASS다. 이 단계 이후 CSS/레이아웃을 변경하면 GitHub Actions의 회귀 검사로 같은 조합을 재검사한다. 전체 프로그램을 배포 가능한 상태로 확정하는 마지막 관문은 9단계 Windows EXE 통합 검증이다.
